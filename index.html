핵심 요구사항 분석

  • iOS/Android 동시 출시를 위한 크로스플랫폼 앱 개발 (Flutter 권장)
  • 이메일 및 SNS 회원가입 + 외국인 사용자/상담사/관리자 3단계 권한 분리
  • 분야별 상담 카테고리 선택 및 텍스트/이미지 첨부 문의 작성
  • 상담사별 캘린더 기반 예약 가능 시간 조회 및 예약 신청
  • 사용자↔상담사 타임존 자동 변환 처리
  • 예약 확정/취소/변경 알림(푸시 + 이메일) 발송
  • 최소 7개국 언어 지원 (러시아어, 베트남어, 몽골어 등 포함)
  • 아랍어 RTL 레이아웃 완벽 대응 (텍스트·아이콘·이미지 미러링 포함)
  • 고정 UI 텍스트는 사전 리소스(ARB/strings)로 처리, 사용자 콘텐츠는 버튼 클릭 시에만 외부 번역 API 호출
  • 번역 결과 서버 캐싱(원문 해시 키 기반)으로 동일 원문 재호출 방지
  • 관리자 회원 목록 조회/권한 관리, 상담 문의 상태(대기/완료) 변경
  • 사용자 간 차단(Block), 부적절 콘텐츠 신고(Report) → 관리자 검토 후 블라인드/제재
  • 개인정보 보호법 준수 및 API 키 보안 관리 (앱에 키 미노출)

제안 포인트

1. 번역 API 비용 폭증 방지 — 3중 캐싱 아키텍처

  • 1차 — 정적 리소스 분리: 버튼/메뉴 등 고정 UI는 Flutter ARB(intl) 파일에 사전 번역본을 적재하여 런타임에 API를 호출하지 않습니다.
  • 2차 — 명시적 호출 게이트: 사용자 작성 콘텐츠는 "번역 보기" 버튼을 눌렀을 때만 BE 프록시를 통해 Google Cloud Translation API를 호출합니다(앱에 API 키 미노출).
  • 3차 — 영속 캐시: 번역 결과는 (원문 SHA-256 해시 + 출발어 + 도착어)를 PK로 PostgreSQL에 영속 저장하고, Redis에 핫 캐시를 두어 동일 원문 재호출을 0건으로 만듭니다.

2. 아랍어 RTL 완전 대응

  • Flutter Directionality.rtl + flutter_localizations 적용으로 레이아웃 자동 미러링 (아이콘 방향, 패딩, 정렬 포함)
  • 아랍어 폰트(예: Noto Sans Arabic) fallback 및 숫자(아라비아 인도식 vs 표준) 표기 옵션 처리
  • 입력 폼의 커서·자판 방향, 이모지·이미지 좌우 정렬, 슬라이더/스크롤 방향까지 QA 체크리스트로 검증

3. 3단계 권한 + 운영자 도구

  • RBAC 정책 테이블 + JWT 클레임으로 외국인 사용자/상담사/관리자 권한 분리
  • 관리자 웹(Next.js)은 동일 BE 위에 별도 어드민으로 구성 → 운영 효율 확보, 보안 경계 분리
  • 신고·차단·블라인드는 상태 머신(접수 → 검토 → 처분)으로 명세화하여 감사 추적 가능

4. 산출물 완성도 우선 — 단계별 데모 인수인계

  • 1순위(산출물 완성도) 충족을 위해 마일스톤 종료 시마다 데모 + 산출물 패키지(요구사항 정의서, 화면 설계서, ERD, API 명세서, 디자인 원본, 소스 코드, 매뉴얼) 단계 인수인계
  • 연내 런칭 일정을 보호하기 위해 실시간 채팅·결제는 명시적으로 범위 외(Out of Scope)로 고정

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

국내 거주 외국인이 언어 장벽 없이 법무법인 외국인센터의 상담을 신청·예약할 수 있는 다국어 전용 모바일 플랫폼을 구축합니다. 아랍어를 포함한 최소 7개국 언어를 지원하고, 외부 번역 API 비용을 최소화하는 캐싱 아키텍처를 적용한 MVP 모델을 연내 런칭하는 것이 목표입니다. 클라이언트사는 내부 IT 인력이 없으므로 기획·디자인·개발·배포를 일괄 수행하는 턴키 방식으로 진행합니다.

3. 기능 요구사항

3.1 회원 및 권한 관리

  • [필수] 이메일 회원가입/로그인 및 SNS 연동 로그인 (Google, Apple, Kakao)
  • [필수] 외국인 사용자/상담사/관리자 3단계 권한 분리 (RBAC + JWT 클레임)
  • [필수] 개인정보 수집 동의(다국어 약관), 프로필 관리, 회원 탈퇴

3.2 상담 및 예약

  • [필수] 분야별 상담 카테고리 선택, 텍스트 + 이미지 첨부 문의 작성
  • [필수] 상담사별 캘린더 기반 예약 가능 시간 조회 및 예약 신청
  • [필수] 사용자↔상담사 타임존 자동 변환 (IANA TZ DB 기준)
  • [필수] 예약 확정/취소/변경 시 푸시 + 이메일 알림(수신 언어 우선)
  • [범위 외] 실시간 채팅 — MVP 단계 제외 (단순 문의 접수 및 연락처 안내 위주)

3.3 다국어 지원 및 번역 최적화 (핵심)

  • [필수] 최소 7개국 언어 지원 (영어, 러시아어, 베트남어, 몽골어, 아랍어, 중국어, 한국어 권장 — 협의)
  • [필수] 아랍어 RTL 레이아웃 완벽 대응 (텍스트·아이콘·이미지 미러링)
  • [필수] 고정 UI 텍스트는 ARB/strings 리소스로 사전 처리 (API 호출 없음)
  • [필수] 사용자 작성 콘텐츠는 "번역 보기" 버튼 클릭 시에만 BE 프록시를 통해 외부 번역 API 호출 (앱에 API 키 미노출)
  • [필수] 번역 결과는 (원문 해시 + 출발어 + 도착어) 키로 PostgreSQL 영속 저장 + Redis 핫 캐시 → 동일 원문 재호출 0건

3.4 관리자 시스템 및 플랫폼 운영

  • [필수] 전체 회원 목록 조회 및 권한 관리
  • [필수] 접수된 상담 문의 목록 조회 및 상태(대기/완료) 변경
  • [필수] 사용자 간 상호 차단(Block) 기능
  • [필수] 부적절 콘텐츠 신고(Report) 접수 → 관리자 검토 → 블라인드/제재 처리 + 감사 로그
  • [필수] 고정 UI 다국어 리소스 업로드 및 배포 기능
